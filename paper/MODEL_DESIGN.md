# Модель: потоковый вероятностный прогноз итогового значения (черновик архитектуры)

Рабочее название: **SettleCast** (варианты: MarketCast, StationStream).
Статус: черновик для обсуждения, 6 ноября 2026. Ничего ещё не обучено.

---

## 1. Постановка задачи

Для события e (станция s, местные сутки D) и **любого момента t** от открытия рынка до конца D
выдать распределение итогового значения по правилам расчёта:

```
p_t(V = k | всё, что опубликовано к моменту t),   k — целые градусы в единицах рынка
```

Отличия от существующих работ:

* **не сетка и не реанализ**, а конкретная станция и **точный таргет по правилам расчёта**
  (routine METAR, округление, местные сутки, режимы правил; резолвер, FINDINGS §6);
* **один прогноз, непрерывно обновляемый во времени**, от «на завтра» до «текущий час»,
  а не отдельные модели для разных горизонтов;
* **строго as-of:** на входе только то, что было опубликовано к t (время публикации прогонов и
  сводок, а не время инициализации или наблюдения);
* оценка против **рынка с реальными деньгами** в тот же момент t, плюс торговый бэктест.

---

## 2. Входы: поток событий

Всё, что приходит по ходу времени, — это **токены** с временем публикации τ ≤ t.

| Тип токена | Содержимое | Источник |
|---|---|---|
| **прогон модели** m (init i) | траектория на сутки D по часам: T2m, радиация, облачность, ветер (u, v), точка росы; агрегаты: max, время max; lead time | Open-Meteo Single Runs (8 моделей, 00/06/12/18z) |
| **прогон ансамбля** | квантили / среднее и разброс членов | AIFS-ENS, AIGEFS, GEFS, ENS (позже) |
| **сводка METAR** | T, Td, облачность и нижняя граница, ветер, давление, явления, routine / SPECI | IEM / AWC |
| **минутные данные** | T каждые 1–10 мин (где есть) | ASOS 1-мин (США), JMA, NEA |
| **ошибки прошлых дней** | ошибка каждой модели на этой станции за прошлые дни | вычисляется из истории |
| **(опц.) рынок** | цены бакетов, глубина стакана | сделки, логгер стакана |

Каждый токен = `[тип, источник (модель / станция), признаки, τ (время публикации), Δ = t − τ]`.

Контекст события: эмбеддинг станции, широта / долгота / высота, расстояние до моря, единицы
(°C / °F), правило расчёта (режим), сезон (день года), местное время t, часы до конца D.

## 3. Архитектура

```
токены событий ──► энкодер токенов (MLP по типу токена) ─┐
траектории прогонов ─► 1D-свёртка / маленький трансформер ─┤
                                                           ├─► трансформер по множеству / последовательности
контекст события (станция, время, правило) ───────────────┘     событий (attention, позиционное кодирование по Δ)
                                                                          │
                                                          [CLS]-представление на момент t
                                                                          │
                                         голова распределения по целым k (относительно центра c)
                                                                          │
                     ограничения правил: P(k < M_t) = 0, где M_t — уже достигнутый максимум дня D
                                                                          │
                                                       p_t(k)  →  вероятности бакетов
```

Ключевые решения:

* **Множество, а не фиксированный вектор признаков.** Модели и сводки приходят нерегулярно,
  какие-то отсутствуют (JMA с мая, GEM с августа). Attention по множеству токенов с маской
  естественно с этим справляется, без ручного заполнения пропусков.
* **Время через Δ = t − τ.** Модель сама учится, насколько стареет прогон или сводка.
* **Общая модель для всех станций** с эмбеддингом станции: делится закономерностями
  между городами (данных на один город мало), но выучивает особенности каждого.
* **Голова распределения:** дискретное распределение по смещениям k − c (c — центр, например
  среднее последних прогонов с поправкой станции). Варианты:
  1. softmax по ~25–41 смещениям;
  2. параметрическое (смесь дискретизированных нормальных / skew), устойчивее при малых данных.
* **Жёсткое правило:** внутри дня D значения ниже уже достигнутого максимума запрещены.
  Маска применяется до нормировки.

Размер: ~1–5 млн параметров, обучение на одной GPU (или CPU) за часы.

## 4. Варианты с рынком (market-aware)

* **M0 — без рынка:** чистый погодный прогноз. Основная модель для статьи.
* **M1 — рынок как вход:** цены бакетов в момент t как токены. Модель учится, когда рынок
  систематически ошибается. Риск утечки: только цены до t.
* **M2 — лог-пул поверх M0:** `log p = α·log p_market + β·log p_M0 + γ`, веса зависят от
  контекста (горизонт, город, режим). Интерпретируемо, легко сравнить с литературой (isotherm).

Для статьи: M0 против рынка (может ли модель сама по себе), затем M1 / M2 (что модель добавляет к рынку).

## 5. Обучение

* **Выборка:** для каждого события случайные моменты t (или сетка), состояние = все токены с τ ≤ t.
  Взвешивание, чтобы одно событие не давало десятки почти одинаковых примеров
  (урок B2, FINDINGS §15).
* **Функция потерь:** log-loss целого значения + RPS (дискретный CRPS) по бакетам.
  Опционально: калибровочный штраф.
* **Предобучение:** Previous Runs 2024–2026 (длинная история, время публикации приближённое),
  затем дообучение на Single Runs (точное as-of).
* **Валидация:** walk-forward по месяцам. Финальная проверка — нетронутый период, выбирается
  после докачки данных (PLAN §3).
* **Калибровка:** temperature scaling на валидации.

## 7. Оценка

* Brier, log-loss, RPS по бакетам **в одни и те же моменты t**, по полосам времени
  (D−1 день / ночь D / утро / день) и по городам, режимам правил, сезонам.
* Калибровочные диаграммы, острота прогноза.
* Против рынка: разница метрик с бутстрапом по город-дням; когда модель лучше рынка.
* Торговый бэктест: вход при положительном матожидании после комиссии, переоценка позиций
  каждый час, цены входа по стакану (логгер) или по сделкам; доходность, просадка, ёмкость.
* Абляции: без METAR / без минутных данных / без прогнозных радиации и облачности /
  без ошибок прошлых дней / без 06z-18z / без предобучения.

## 9. Риски

* **Мало точных as-of данных** (Single Runs только с апреля 2026). Предобучение на Previous Runs
  частично решает.
* Нейросеть может не обогнать бустинг или EMOS на таком объёме. Это тоже результат, но
  слабее. Поэтому сильные простые бейзлайны обязательны.
* Модель может не побить рынок. Для статьи-бенчмарка это допустимо, если сравнение строгое.
* Утечки из будущего через время публикации: везде использовать τ (публикацию), а не init.
