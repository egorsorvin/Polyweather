## 1. Цель и решающий вопрос

Цель — зарабатывать на погодных рынках Polymarket. Решающий вопрос этапа исследования:

> **Можем ли мы в момент сделки давать вероятность бакета точнее рыночной цены, с запасом
> на комиссию 2–4 % (или забирая его как мейкер)?**

Если нет ни в одном варианте (A, B, C ниже), честно останавливаемся или меняем идею,
не тратя время на бота и UI.

## 2. Что было не так в старой версии (аудит)

**Методология**
- Оптимизировалась не та метрика: «bucket accuracy» и MAE. Для торговли важны калибровка
  вероятностей (Brier / log-loss / CRPS) и сравнение с рынком.
- Вероятности собирались неправильно: LightGBM предсказывал одну точку, к ней сдвигались
  члены ансамбля ICON, разброс брался от ICON. Ансамбли NWP слишком узкие, поэтому
  вероятности были переуверенными, и появлялись ложные edge.
- Обучение и прод не совпадали. В обучении `max(hourly temperature_2m_previous_day1)`,
  в проде дневной `temperature_2m_max` последнего прогона.
- `previous_day1` = значение для каждого часа из прогона примерно за 24 ч до этого часа.
  Для пиковых часов это прогоны, выпущенные днём D−1, которых в момент сделки утром D−1
  ещё нет. Это утечка из будущего.
- `knmi_seamless` и `dmi_seamless` вне Европы в 73 % дней равны ECMWF, то есть мусорные дубли.
- LightGBM почти ничего не давал. Среднее моделей с поправкой на смещение за 60 дней:
  36.3 % точности против 37.9 % у LightGBM.
- Отбор максимального edge среди бакетов давал winner's curse.
- Почасовой максимум систематически ниже настоящего, отсюда часть «смещения +1 °C».

**Данные и станции**
- **Токио стоял на координатах Нариты, а рынок резолвится по Ханэде (RJTT).** Это около 60 км.
- Города выбирались по точности модели, а надо по неэффективности рынка и ликвидности.

**Стратегия и исполнение**
- Выходы в live-режиме не исполнялись: `sell_yes` нигде не вызывался.
- Покупка считалась исполненной сразу, без проверки fill.
- Цена выхода бралась из Gamma `outcomePrices` (середина или последняя сделка), а не bid.
- Стоп-лосс 20 % на бинарном рынке с тонким стаканом съедает ожидание.
- «Завтра» считалось как дата UTC + 1, для Веллингтона и Америк это другой локальный день.
- Ключ weather.com был зашит в код (сейчас отвечает `401 throttled`).

## 3. Что мы узнали о данных

**Рынки** (подробности в `FINDINGS.md`)
- Gamma: `/events?tag_slug=weather`, `limit` ≤ 100, `offset` < 2000, поэтому выгружать окнами по `endDate`.
- Сделки: Data API **v2** `/v2/trades?eventId=…`, курсорная пагинация (v1 закрыт).
  Есть время, цена, объём, сторона, кошелёк — с момента открытия рынка.
- Ценовые ряды: CLOB `/prices-history` с явными `startTs`/`endTs`, шаг 10 мин.
- Истории стакана публично нет (платно: Oddpool с марта 2026, MarketLens).
- Объёмы большие: медиана $40–200K на событие. Топ: Лондон, NYC, Сеул, Гонконг,
  Шанхай, Париж, Веллингтон, Токио.
- `endDate` номинальный, 12:00 UTC у всех городов. Привязываться надо к местному времени
  целевого дня.

**Правила резолва менялись** (таргет надо строить по правилу каждой даты)
- до ~июля 2026: Wunderground daily history, целые градусы;
- август–сентябрь 2026: NOAA `weather.gov/wrh/timeseries`;
- с октября 2026: максимум routine METAR по T-группе (десятые °C, SPECI не считаются),
  рынки США в целых °F;
- Гонконг: Hong Kong Observatory, «Absolute Daily Max», 0.1 °C;
- смены станций: Париж LFPG → LFPB, Денвер KBKF → KDEN.

**Комиссии**
- С апреля 2026 тейкер платит примерно `0.05·p·(1−p)` за акцию: 2.5 % при p=0.5, 4 % при p=0.2.
- Мейкер не платит и получает ребейты. Аргумент торговать лимитками.

**Open-Meteo**
- Бесплатно: 600/мин, 5 000/час, 10 000/день на IP. Запросы «взвешенные»: >10 переменных
  или >2 недель считаются за несколько.
- С облачного IP Claude лимит всегда выбран, поэтому качаем с ПК или сервера пользователя.
- **Single Runs** (точный прогон «как был опубликован») доступны только **с 2026-04-02**
  (JMA с 05-13, GEM с 08-19). Похоже на скользящее окно, **старые прогоны могут исчезать**,
  поэтому качаем срочно.
- Рабочие имена моделей для Single Runs: `ecmwf_ifs025, ecmwf_aifs025_single, icon_global,
  gfs_global, gem_global, ukmo_global_deterministic_10km, jma_gsm, meteofrance_arpege_world`.
  `gfs025` пустой. GraphCast в Previous Runs пустой.

## 4. Главный вывод сегодняшнего дня: рынок откалиброван

~98 тыс. снимков «бакет × момент» (`research/market_calibration.py`), снимок D−1 12:00 по местному времени:

| цена бакета | n | сбылось − цена | s.e. |
|---|---|---|---|
| 0–10 % | 63 717 | −0.13 п.п. | 0.05 |
| 10–30 % | 19 662 | −0.76 п.п. | 0.28 |
| 30–50 % | 12 518 | +0.83 п.п. | 0.43 |
| 50–100 % | 2 601 | +0.94 п.п. | 0.90 |

- Цена ≈ вероятность. Слабый favourite–longshot bias около 1 п.п., меньше комиссии и спреда.
- Механические стратегии на одних ценах («покупай хвосты», «покупай фаворита») после комиссии в минусе.
- Сумма цен бакетов ≈ 1.003.
- **Планка для модели — Brier рынка:** 0.0755 (D−1 12:00), 0.069 (D 12:00), 0.036 (D 15:00).
- Оговорка: использована цена последней сделки, а реальная покупка идёт по ask, то есть чуть хуже.

**Следствие:** edge возможен только за счёт *информации*: лучшая вероятность, скорость
или внутридневные наблюдения.

## 6. Подход к модели (согласован в обсуждении)

Физические модели (ECMWF, ICON, GFS…) — сырьё, а не конкурент рынку. Рынок их уже видит.
Мы строим **свой вероятностный прогноз** поверх них. Лестница, где каждый шаг должен побить
предыдущий в walk-forward по CRPS и log-loss, а затем рынок по Brier на тех же бакетах и в те же моменты:

```
B0  ICON как есть + N(μ, σ_город/сезон)            простейший бейзлайн
B1  EMOS: μ = a + Σ bᵢ·моделиᵢ,  σ² = c + d·разброс²
    обучение минимизацией CRPS на скользящем окне 30–90 дней
B2  бустинг на остатке (target − μ_EMOS) с вероятностным выходом
    (NGBoost / LightGBM-квантили / классификатор по бакетам), обучение на всех городах сразу;
    ловит нелинейности: ветер с моря, облачность, сезон
B3  смешивание с ценой рынка: p = f(logit(модель), logit(рынок)), веса подбираются на истории
```

**Таргет** — строго значение по правилам резолва: станция резолва, местные сутки,
правило конкретной даты, округление в бакет. Тогда систематика станции
(например, «модели занижают RKSI на 1.8 °C») выучивается автоматически.

**Момент решения T** фиксирован (например, D−1 12:00 местного). Признаки берутся только
из прогонов, *опубликованных* к T (init + задержка публикации). Одна и та же функция
используется и в обучении, и в проде.

## 7. MVP и этапы

**Этап 1. Исследование без денег (~1–2 недели) → решение «есть edge или нет»**
1. Таргет по правилам резолва: исходы бакетов из Gamma плюс METAR-архив IEM для
   непрерывного значения.
2. **1a. Гипотеза C:** METAR + сделки. Как быстро рынок реагирует на наблюдения дня D.
3. **1b. Гипотезы A/B:** B0 → EMOS → бустинг на Single Runs (апр–ноя 2026), бэктест
   против рынка с комиссией, тейкер против мейкера.
4. Отчёт: где есть edge, сколько, по каким городам и в какое время.

**Этап 2. Paper-бот + UI (только при положительном этапе 1)**
- Бот на сервере пользователя торгует только проверенной стратегией.
- Логгер стакана и прогнозов в БД с бэкапом вне сервера, чтобы данные больше не терялись.
- Веб-дашборд: сигналы, позиции, PnL, «модель против рынка» в реальном времени, калибровка.

**Этап 3. Малые реальные деньги**, когда paper-результаты недели совпадают с бэктестом.
